# FAST parameter envelope audit

Audited baseline e7b2f6de69dda341bc398d49ec719d5957af78e7.
Scope: fw_rate_control_params.c metadata, FixedwingRateControl.hpp Param wrappers,
FixedwingRateControl.cpp plumbing/publication, FastControl.hpp, host/source tests,
historical audit reports and fresh generated parameters.json.

| Parameter | Unchanged default | Old ceiling | New metadata/runtime range |
|---|---:|---:|---|
| FLAP_FAST_EN | 0 | boolean | boolean, unchanged |
| FLAP_FAST_K | 1 | 1 | 0..5 |
| FLAP_FAST_MAX | .005 | .005 | 0...020 |
| FLAP_FAST_TON | .15 | .15 | 0...180, strictly below TOFF |
| FLAP_FAST_TOFF | .18 | .18 | 0...200, strictly above TON |
| FLAP_FAST_SLEW | .05 | .05 | .000001...200 |

The former five ceilings were present BOTH in parameter metadata and runtime validation.
K=1.5 previously made config_ok false; step invalidated actual/readiness and returned zero.
No independent hidden K clamp was found in production source. ParamFloat values are copied
directly into Config without further tuning transformations. EN uses ParamBool.
Changing metadata alone would not have removed the runtime restriction.

Additional rejection conditions: finite values required for every tuning float; TON>=0,
TON<TOFF; positive slew. TOFF positivity follows from TON>=0 and TON<TOFF.
Metadata cannot encode cross-parameter inequalities: individual values in range can still form
an invalid pair. Both parameter descriptions explicitly disclose the relationship and the
new config_invalid field reports it. TOFF=0 is therefore not operational with any legal TON.
SLEW metadata and runtime now share an explicit 1e-6 positive lower bound. This excludes
tiny positive sub-minimum values too; it is intentional, documented, and tested.

Other zero-output causes (not parameter ceilings): disabled, non-Mission/VTOL/transition/
disarm/landed/failsafe/configuration guard, reset, invalid features, nine-new-frame readiness,
nonfinite source, model/live age >100000 us or time reversal, dt<=0 or dt>.1,
and burden-domain exclusion. These behaviors are unchanged.
MAX symmetric clamp, min(model gate,live gate), T_SAFE projection, slew, and final output
clipping can further reduce output. K alone cannot defeat MAX.

The runtime constants are centralized in FastControl.hpp. C metadata mirrors them manually;
source_isolation_test.py parses both and compares maxima, minima and defaults. Fresh build
parameters.json independently showed matching values. No generated source is hand-edited.
The old host assumption MAX=.010 invalid is replaced with nextafter(new_max,+Inf).
Default-boundary tests remain default tests, not a hidden runtime ceiling.
Old build logs/patch snapshots document past commits; they are not authoritative current limits.
FAST_CONTROL_IMPLEMENTATION.md now references this envelope. Earlier conservative-envelope
statements describe historical implementation and are superseded by this report.

## Projection proof and test limits
For any eligible pair, both |T|<TOFF<=.20, so the intersection of the two T_SAFE intervals
contains zero. Projecting final into that intersection cannot force an unsafe sign.
Current ceilings MAX<=.02 and TON<=.18 already imply gated authority <=.20-|T|
(full gate or linear fade); therefore the .20 projection is normally redundant even at the
expanded ceilings. We do not fabricate an activation case by bypassing legal config.
Tests check both inequalities over 1080 synthetic cases and a pre-existing .02 actual
contracting immediately near .199 despite slow normal ramp-down.
At burdens already outside .20, fail-zero cannot repair the unsafe baseline; it only adds zero.

config_invalid=!config_ok on EVERY evaluated step, even disabled/ineligible/reset steps.
If Run never calls step (e.g. full manual path), default Decision leaves config_invalid=false.
This is not an assertion that such a path evaluated valid configuration. No configuration error
is reclassified as nonfinite_fallback or disabled_by_state.
Publication copies the boolean into flap_fast_control; schema is regenerated by the build.

Research ceilings are not recommended settings or flight authorization. No vehicle parameters
were written. Model coefficients and model-frame semantics remain byte-identical to e7b2f6de69.
